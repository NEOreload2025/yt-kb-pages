15 分鐘學完 CLAUDE.md
從入門到精通

CLAUDE.md 是 Claude Code 每次對話前強制讀取的指令檔（Codex 對應 AGENTS.md），寫好它是用 AI 投資報酬率最高的一件事。
1

它是什麼？

CLAUDE.md 是 Claude Code 在每次新對話開始時「自動注入 context」並強制遵守的指令檔，可視為 AI 的最高指導原則。

放在專案裡、開新對話時自動載入，連 AI 也不能違背。

把它寫好，你就省下每次開新對話都要重新解釋專案架構與規矩的時間——工作流程的細節、未言明的默契、最容易踩雷的眉角，都能靠它一次講清楚。

2

三個層級（規則會疊加）

越接近「正在編輯的工作檔案」，規則就越精準。三個層級會疊加生效，互不衝突。

User Level
~/.claude/CLAUDE.md
全域生效。放個人偏好（程式風格、常用工具、輸出語言繁體中文）。
Project Level
./CLAUDE.md
專案共享。團隊協作規範、架構決策、禁用模式、測試要求。
Local Level
.claude/CLAUDE.local.md
機器專屬。本地路徑、實驗性設定、不想 commit 的暫時規則。
3

優先序：Local > Project > User

同一個規則在多層出現時，最靠近當下編輯檔案的那一層勝出。這讓你能在不改動團隊共識的前提下，針對個人習慣或機器環境做微調。

4

常見必寫項目（建議清單）

1
輸出語言固定為 繁體中文（無論影片字幕為何種語言）
避免 AI 隨意切換簡體/英文，統一知識庫語言
2
專案架構概覽（目錄結構、關鍵模組、資料流向）
新對話不必重問「這專案長什麼樣」
3
開發規範（命名慣例、Git flow、測試門檻、Lint 設定）
統一團隊代碼風格，減少 PR 來回修改
4
常用指令別名（開發/測試/部署一鍵跑）
AI 也能直接呼叫，不必每次查 package.json
5
禁用/慎用模式（如：禁止直接改 production 設定、禁止硬編碼密鑰）
防止 AI 犯低級錯誤的護欄
5

最小可用範本（複製即用）

建立專案根目錄的 CLAUDE.md，貼上以下內容再依專案微調：

提示： 這個範本已內建「輸出繁體中文」規則，無論來源語言為何，AI 產出的文件、回覆、代碼註解都會是繁體中文。 
# CLAUDE.md - 專案指令檔

## 輸出語言
所有回覆、文件、代碼註解、Commit 訊息統一使用繁體中文，無論輸入語言為何。

## 專案架構
- src/ - 主要源碼
- tests/ - 測試檔案
- docs/ - 文件

## 開發規範
- 命名：PascalCase (類別)、camelCase (函數/變數)、UPPER_SNAKE_CASE (常數)
- Git: Conventional Commits (feat:/fix:/docs:/refactor:)
- 測試: 新功能必須含單元測試，覆蓋率 ≥ 80%
- Lint: 提交前需通過 ESLint + Prettier

## 常用指令
- dev: npm run dev
- test: npm run test
- lint: npm run lint
- build: npm run build

## 禁用事項
- ❌ 硬編碼 API Key / Secret / Token
- ❌ 直接修改 production 環境設定
- ❌ 未經審查直接合併 main 分支

## 參考文件
- AGENTS.md (Codex 專用)
- ARCHITECTURE.md (架構決策記錄)
6

常見問題

Q1
CLAUDE.md 改了但 AI 沒生效？
Claude Code 只在「新對話」讀取。已開啟的對話需重啟或用 /init 重新載入。
Q2
想暫時覆蓋某條規則？
在 Local Level (.claude/CLAUDE.local.md) 寫相反規則，優先序最高，不會污染專案共識。
Q3
團隊成員用 Codex (AGENTS.md) 怎麼同步？
內容保持同步，只是檔名不同。CI 可加入檢查兩檔一致性。

一次投入、永續回收。下次開新對話，你會發現 AI 已經「懂你的專案、守你的規矩、說你的語言」。
