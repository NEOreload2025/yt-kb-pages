15 分鐘學完 CLAUDE.md
從入門到精通

CLAUDE.md 是 Claude Code 每次對話前強制讀取的指令檔（Codex 對應 AGENTS.md），寫好它是用 AI 投資報酬率最高的一件事。
1

它是什麼？

CLAUDE.md 是 Claude Code 在每次新對話開始時「自動注入 context」並強制遵守的指令檔，可視為 AI 的最高指導原則。

放在專案裡、開新對話時自動載入，連 AI 也不能違背。

把它寫好，你就省下每次開新對話都要重新解釋專案架構與規矩的時間——工作流程的細節、未言明的默契、最容易踩雷的眉角，都能靠它一次講清楚。

2

三個層級（規則會疊加）

越接近「正在編輯的工作檔案」，規則就越精準。三個層級會疊加生效，互不衝突。

User Level
~/.claude/
所有 session 通用的個人長期偏好。例如「只用繁體中文輸出」「不要幫我加無謂的註解」。
Project Level
專案根目錄
這個專案共通的規則，跟著程式碼一起上 git，團隊每位成員都會吃到這份設定。
Nested Level
子資料夾內
特定資料夾專屬的規則。例如 frontend / backend 各放一份，語言風格與測試方式分開管。
💡 額外層級：CLAUDE.local.md

放在同一個資料夾、不上 git、不進版本控制——專門放個人癖好或本機測試用的本機設定。

3

建立：用 /init，但別照單全收

Claude Code 提供 /init 指令幫你自動產生一份 CLAUDE.md 模板，但它寫出來的內容通常太完整。

因為很多其實是 Claude 靠 Explore subagent 自己就能找到的資訊，照單全收會：

  • 浪費 token
  • 塞爆 Instruction Budget（注意力）
  • 淹沒真正重要的規則，造成「規則越多越沒用」
⚠️ 正確心態

/init 給的是「雛形」，不是「最終版」。下一步要用減法三問把多餘的東西砍掉。

4

減法三問：該不該從 CLAUDE.md 拿掉？

面對一條規則，問自己這三個問題。如果答案指向「不必寫」，就大膽砍掉。

1
Claude 的 Explore subagent 能不能自己發現？
如果能，就別寫——把 AI 當作可以自己查資料的工程師。
2
這條資訊是不是大部分工作都用得到？
只有特定資料夾才用，就改放到 Nested Level，不要污染根目錄。
3
幾個月後還會成立嗎？
會過時的就別留；過時規則比沒有規則更糟，因為 AI 會照著錯的東西執行。
5

加法五問：哪些隱性知識該寫進去？

減完之後，再回頭看：這些「只有你知道、文件也沒寫」的東西，才是 CLAUDE.md 的真正價值。

1
有沒有絕對不能搞錯的規定？
例如「價格必須含稅」、「金額一律到小數第二位」。
2
有沒有固定處理方式？
例如「改價格一定要從那張試算表開始改」。
3
改完這裡，還有哪裡要跟著改？
列出連動關係，避免 AI 改 A 沒改 B 這種經典失誤。
4
做到什麼程度才算完成？
定義「完成前的檢查清單」，讓 AI 自己驗收。
5
遇到不懂的事，去哪裡找答案？
指向文件位置（內網 wiki、Notion、某個 repo），比請 AI 自己猜有效十倍。
6

維護 = 新增 + 修剪

新增：用 /insights 分析歷史對話，找出反覆發生的問題，只加真正能解決問題的規則——不要看到一個 case 就加一條。

修剪兩個對象：

模型變強後不再需要的
Claude 官方曾為了新一代模型（如 Fable 5 / Opus 5）刪掉 80% 的規則，結果能力不減反而變強。
跟真實情況不符的過時規則
對照最新的官方 Prompting Guide，判斷哪些已過時，該砍就砍。
🔁 把它當作活文件

CLAUDE.md 不是寫一次就好，而是隨著專案與模型演進持續修剪的高品質小文件。

7

內容分流：別全塞 CLAUDE.md

不同性質的指令，適合放在不同地方。把長內容、死命令、跨工具同步分別處理。

Skill（流程）
/skill-name
長流程（例如發布版本前十幾項檢查）放成 Skill，需要時再呼叫，不佔 context。
Hook（強制攔截）
hooks/*
絕對不能犯的死罪（例如 API key 不能進 git）用 Hook 程式強制檔住，不能只靠文字提醒。
AGENTS.md（同步）
AGENTS.md ↔ CLAUDE.md
Codex 用 AGENTS.md、Claude Code 用 CLAUDE.md。讓其中一份 reference 另一份，只維護 single source of truth。

一句話總結

CLAUDE.md 寫得少、寫得準、寫得活的話，是 AI 時代投資報酬率最高的一件事——它讓每一次新對話，都自動帶著團隊累積下來的智慧。
