AI 工作流 · 入門指南

15 分鐘學完 CLAUDE.md
從入門到精通

CLAUDE.md 是 Claude Code 每次對話前強制讀取的指令檔。
寫好它，是用 AI 投資報酬率最高的一件事。

01 · 基礎觀念

它是什麼？

放在專案裡的指令檔，每次開對話時自動注入 context。它是給 AI 的「不可違背的最高指導原則」。寫得好，就不用每次開新對話重複解釋專案的架構與規矩。

02 · 架構

三個層級，規則會疊加

越接近工作檔案的規則越精準。針對不同範圍，放對應的層級。

LEVEL 1

User Level

~/.claude/

所有 session 都通用。放個人長期偏好，例如「只用繁體中文輸出」。

LEVEL 2

Project Level

./CLAUDE.md

專案共通規則，放在專案根目錄，跟著程式碼一起上 git。

LEVEL 3

Nested Level

frontend/CLAUDE.md

特定資料夾專屬規則，例如 frontend、backend 分別管理。

額外技巧：用 CLAUDE.local.md 放個人癖好，不上傳到 git。
03 · 建立

用 /init 起步，但別照單全收

/init 會自動產生一份「太完整」的模板——但很多資訊，其實 Claude 自己就能靠 Explore subagent 找到。照單全收會浪費 token、塞爆 Instruction Budget，淹沒真正重要的規則。

04 · 過濾

減法三問：留下真正重要的

面對 /init 產出的長清單，逐一用這三題篩選。

1

Claude 的 Explore subagent 能不能自己發現？

能就別寫，避免浪費 context。

2

這條資訊是不是大部分工作都用得到？

只有特定資料夾才用得到的，放 Nested Level 就好。

3

幾個月後還會成立嗎？

會過期的內容，現在就別留。

05 · 加值

加法五問：找出該寫進去的隱性知識

做完減法，再回頭檢查——有沒有這些「只有你知道」的關鍵知識？

1

有沒有絕對不能搞錯的規定？

價格必須含稅。
2

有沒有固定處理方式？

改價格一定從試算表開始，不能直接改前端。
3

改完這裡，還有哪裡要跟著改？

明確標註連動關係，避免改一漏十。

4

做到什麼程度才算完成？

寫下完成前的檢查清單。

5

遇到不懂的事，去哪裡找答案？

明確指向文件、設計稿、Schema 的存放位置。

06 · 維護

維護 = 新增 + 修剪

CLAUDE.md 不是寫完就好，要持續跟著專案演化。

＋

新增：/insights

用 /insights 分析對話歷史，找出反覆發生的問題，只加真正需要的規則。

－

修剪：模型已變強

模型變強後不再需要的規則就刪掉。官方為 Fable 5 / Opus 5 刪掉 80% 規則，能力反而沒退步。

－

修剪：過時規則

刪掉不再符合現況的規則。對照最新官方 Prompting Guide 判斷哪些已過時。

07 · 分流

內容分流：別全塞 CLAUDE.md

不同性質的內容，應該放在不同的地方各司其職。

Skill

長流程任務

例如發布版本前的十幾項檢查。放在 Skill，需要時再呼叫，不要一直佔用 context。

Hook

絕對不能犯的死罪

例如 API key 不能進 git。用 Hook 程式強制攔截，不能只靠文字提醒。

AGENTS.md

Codex 對應檔

CLAUDE.md ↔ AGENTS.md 之間維持 single source of truth，一份 reference 另一份。

寫一次，受用每一次

CLAUDE.md 是你跟 AI 一起工作的契約。寫得精準、持續維護，它就會在每一個新對話裡替你把關——讓 AI 從「聰明但陌生」變成「熟悉你專案的老同事」。
